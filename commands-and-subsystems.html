Fundamentals: The Basics of Commands and Subsystems.

The majority of the code will be made up of commands and subsystems. In this lesson, you will learn what they are and how to use them.

Page 1: Commands

Commands are the pieces of code that directly communicate with the robot. You can think of a Command as the task you assign your robot. Commands rely on other pieces of code called subsystems. While a command can be seen as the function of the robot, a subsystem can be seen as an individual part of the robot. For example, a drive command will use the Drivetrain subsystem.

Parts of a Command

A command has multiple important parts. The class contains the name of the command as well as a declaration of the extension of the command function.

Commands should have a getRequirements method. This method ensures 2 different commands don't use the same subsystem, which can result in issues with the subsystem attempting to output in 2 different places.

Each command also typically has 4 methods: initialize, execute, isFinished, and end.

initialize is called only once when the robot is enabled. In our command, we might call a function in our driveTrain subsystem to start accelerating.

execute runs repeatedly while the command is active. In our command, we might call a function in our driveTrain subsystem to remain at a constant speed.

The boolean function isFinished also runs repeatedly while the command is active. If the function returns "true", execute will stop running and the method end will run. In our command, we might want to run the command continually, as we want our robot to keep driving. In a shoot command, isFinished might be used to check if all materials have been shot.

The function end runs one time when isFinished returns true. Even if our isFinished method cannot return "true", the end method can be used when stopping the robot.

Page 3: Executing Commands

We've now created a Command; let's find out how to run it. Commands are typically either run from a controller or from your robot's RobotContainer class.

RobotInit and robotPeriodic are also special methods of the robot class.

Commands are executed through the CommandScheduler. Once the command is executed, it will run the instantiate method.
